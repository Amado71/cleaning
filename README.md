# Cleaning plan · План уборки · Siivoussuunnitelma

> Планировщик недельного маршрута уборки для небольшого жилого здания.
> Работает офлайн, без сборки и зависимостей. Данные хранятся на устройстве.

**Languages:** RU · EN · FI (переключатель в правом верхнем углу)
**Stack:** vanilla HTML + CSS + JS (≈ 900 строк вместе с данными)
**License:** MIT

---

## Возможности

- **Маршрут на день** — от чистого к грязному, санузлы в конце. Учитывает время начала, темп и «запас до освобождения комнат».
- **Жильцы** — комнаты закреплены за днями и повторяются каждую неделю. Глубокая уборка санузлов (раз в 28 дней), душевых леек и рам кроватей (раз в 88 дней) появляется автоматически.
- **Периодические задачи** — плинтусы, стены кухни, сливы, полы машинной мойкой. Привязаны к дням недели и повторяются не чаще срока.
- **Прогресс и оценка времени** — «сделано N из M», «осталось ≈ X мин», «конец ≈ HH:MM», предупреждение при перерасходе 2,5 ч.
- **Три языка** — RU / EN / FI, выбор сохраняется.
- **Печать** — одного дня или всей недели, с сохранением чекбоксов.
- **PWA** — устанавливается на телефон/десктоп как приложение (при размещении на HTTPS).
- **Резервная копия** — экспорт в JSON одной строкой, восстановление вставкой.
- **Тёмная тема** — автоматически по системной настройке, принудительно через `data-theme`.

## Файловая структура

```
cleaning/
├── index.html      разметка + подключение скриптов
├── style.css       оформление, тёмная тема, стили печати
├── data.js         переводы RU/EN/FI, комнаты, задачи, периоды
├── app.js          логика: маршрут, рендер, сохранение, PWA
├── manifest.json   PWA-манифест (иконка, название, цвет)
├── sw.js           service worker (кеш для офлайн-работы)
└── icon.svg        иконка
```

Все правки делаются в `data.js` (контент) или `app.js` (логика). `index.html` и `style.css` трогать почти не нужно.

## Быстрый старт

1. Скачайте папку с файлами.
2. Откройте `index.html` двойным кликом в браузере.
3. Готово.

Ничего не нужно устанавливать. Работает на Windows / macOS / Linux / Android / iOS, в любом современном браузере.

### Первичная настройка за 30 секунд

1. Откройте раздел **«Все комнаты: разложить по дням»**.
2. Впишите номера комнат жильцов через запятую или диапазоном: `101-126, 201, 202`.
3. Нажмите **«Разложить»** — номера равномерно распределятся по дням недели.
4. Дальше можно поправить каждый день в поле **«Комнаты»** в шапке дня.

## Установка как приложение (PWA)

### Вариант A — GitHub Pages (рекомендую)

Плюс: стабильный URL → **данные не пропадут при переносе папки**, есть история изменений.

1. Создайте публичный репозиторий `cleaning` на GitHub.
2. Загрузите все файлы через **Add file → Upload files**.
3. **Settings → Pages → Source: Deploy from a branch → main / (root) → Save**.
4. Через 1–2 минуты откроется `https://<ваш-ник>.github.io/cleaning/`.
5. На телефоне откройте URL → меню браузера → **«Установить приложение»** (Chrome) или **«Добавить на главный экран»** (Safari).

### Вариант B — Netlify / Vercel / любой статик-хостинг

Перетащите папку в [app.netlify.com/drop](https://app.netlify.com/drop) — получите HTTPS-ссылку за секунды. Аналогично работает с Vercel, Cloudflare Pages, Surge.

### Вариант C — только локально

Откройте `index.html` в браузере. Всё работает, но **PWA не активируется** — это ограничение браузеров (service worker требует HTTPS или `localhost`). Иконки на рабочем столе не будет, офлайн-кеш не создастся (но и без него файлы локальные — они и так офлайн).

### Про `localStorage` и перенос папки

При открытии через `file://` данные привязаны к **пути** файла. Переименовали/перенесли папку — браузер считает это другим приложением, сохранения не найдёт.

При открытии через **HTTPS** (GitHub Pages) данные привязаны к **домену** — можно свободно переименовывать репозиторий, данные останутся.

**В любом случае** регулярно делайте резервную копию (раздел ниже).

## Настройка

### Убрать комнату, которой нет в здании

Например, у вас нет сауны — удалите три объекта из `data.js`:

```js
{id:"sauna", ...},
{id:"sauna_shower", ...},
{id:"sauna_dressing", ...}
```

И уберите их из массива `ROUTE`:

```js
var ROUTE = [ ... "sauna","sauna_shower","sauna_dressing" ... ] // удалить эти три
```

И из `PERIODS` — все строки, где `rid:"sauna"`, `rid:"sauna_shower"`, `rid:"sauna_dressing"`.

Типичные «лишние» для 1-этажного здания без сауны: `sauna`, `sauna_shower`, `sauna_dressing`, `balcony`, `basement`, `laundry`, `staff_dressing`.

**Мягкий вариант** — не удалять объект, а закомментировать его в `ROUTE`. Объект останется в файле как заготовка, но в план не попадёт.

### Добавить комнату

```js
{id:"myroom", c:"#888", n:"r_myroom", t:[
  ["t_trash","00100",1],        // ключ, маска дней "11111", минуты
  ["t_doors","00100",2],
  ["t_floor","00100",4]
]}
```

Маска дней — строка из пяти символов `0`/`1`: ПН, ВТ, СР, ЧТ, ПТ. Например `"10101"` — пн/ср/пт.

Затем добавьте `"myroom"` в `ROUTE` (в нужное место по маршруту — от чистого к грязному) и добавьте ключ перевода `r_myroom` в каждый язык в объекте `T`.

### Изменить время начала / темп

В шапке каждого дня — выпадающие списки «Начало» и «Темп». Значения по умолчанию (`12:00`, `1.0`) — в объекте `st` в начале `app.js`.

### Изменить лимит 2,5 часа

В `app.js`, константа `LIM = 150` (минуты). Например, `LIM = 180` для 3 часов.

### Изменить правило «13:00 — кухня»

Константа `KT = 780` (13:00 в минутах от полуночи). И `LS = 720` (12:00) — момент, когда можно начинать комнаты.

### Изменить сроки глубокой уборки

В `app.js`, в функции `addRooms`:

- `>= 28` — санузлы комнат (сливы, щётка, пол ластой)
- `>= 88` — душевые лейки и рамы кроватей

Значения в днях.

### Изменить периодические задачи (плинтусы, стены и т.п.)

Массив `PERIODS` в `data.js`:

```js
{id:"p2", rid:"corridor", k:"p_skirting", days:30, wd:4, m:4}
//  id — уникальный ключ
//  rid — id комнаты из ROOMS
//  k — ключ перевода
//  days — минимальный интервал между выполнениями
//  wd — день недели (0=ПН ... 4=ПТ)
//  m — минуты
```

### Перевести интерфейс на другой язык

Все строки лежат в объекте `T` в начале `data.js`. Три ключа верхнего уровня: `ru`, `en`, `fi`. Скопируйте структуру `ru`, переведите значения, добавьте как `var T = {ru:..., en:..., fi:..., XX:...}`. Затем добавьте `<option value="XX">XX</option>` в `index.html` в `<select id="lang">`.

## Резервные копии

`localStorage` — быстрый и удобный, но не вечный. Данные пропадут при:

- очистке «данных сайтов» в браузере
- переустановке браузера
- переименовании/переносе папки (в режиме `file://`)

**Правило:** раз в неделю открывайте раздел **«Резервная копия»**, нажимайте **«Скопировать»** и отправляйте текст в «Избранное» Telegram / заметки / себе в личку.

Восстановление: вставить текст обратно в поле → **«Загрузить»**.

Текстовый формат — обычный JSON, его можно читать глазами, править вручную и хранить в git.

## Известные шероховатости

Две строки в `data.js` пропущены, из-за чего в плане на пару дней видно «сырые» ключи. Быстрый патч — добавьте по одной строке в каждый язык:

**RU** (в объекте `T.ru`):
```js
t_sinks:"Раковины и краны",
p_drains_skirting:"Сливы и плинтусы",
```

**EN** (в `T.en`):
```js
t_sinks:"Sinks and taps",
p_drains_skirting:"Drains and skirting",
```

**FI** (в `T.fi`):
```js
t_sinks:"Pesualtaat ja hanat",
p_drains_skirting:"Viemärit ja jalkalistat",
```

Появятся на: прачечная (`t_sinks` — вт и пт) и её периодическая задача (`p_drains_skirting` — чт).

## Тонкости реализации

**Маршрут.** Сначала идёт подготовка тележки, потом комнаты жильцов (до 12:00), потом остальные помещения по порядку `ROUTE`, в 13:00 — кухня, потом столовая, потом комнаты, которые не успели до обеда, в конце санузлы, в самом конце — завершение и стирка. Свободное время заполняется «запасом» с подсказкой.

**Порядок задач внутри остановки.** Сверху вниз: мусор → стены/поручни → двери/выключатели → подоконники → мебель → сантехника и техника → пол. Задача «сильно залито» (флаг «Малая столовая сильно залита») идёт первой.

**Цвета тряпок.** Автоматически по ключу задачи: санузлы → красная, кухня и столы → зелёная, всё остальное → синяя. Метка видна в шапке карточки.

**Ключи галочек.** Формат `YYYY-MM-DD_stop-id_task-id`. Устойчив к переименованию комнат и дней. Чистятся автоматически через 14 дней.

**Совместимость.** Миграция с `plan_v2` (старая версия в одном файле) работает автоматически при первом запуске: `localStorage` читает `clean_v3`, если пусто — пробует `plan_v2`.
